# Spec：按部署模式控制目录比对

> 本文件记录已经调查并经用户确认的需求事实。

## 1. 问题与范围

- 当前行为：目录比对入口始终显示，`/api/compare/directory`、`/api/compare/directory/path` 和 `/api/compare/directory/summary` 在任何部署环境均可调用；其中路径接口可以读取服务进程有权限访问的服务器目录。
- 目标行为：本地运行时继续支持目录比对；服务器部署时前台不展示目录比对入口，后端同时禁止全部目录比对接口；首页状态文案在两种模式下统一显示“版本比对”。
- 范围：新增明确的本地/服务器部署模式；控制目录入口和三个目录 API；将首页固定“本地版本比对”改为中性文案；保持 Jar、文件、文本比对不变。
- 非目标：本变更不实现用户鉴权、反向代理配置、Jar 上传安全、文件 Diff 内存治理或其他已发现风险。

## 2. 项目证据

- 证据：当前前端、控制器和配置的定位如下。
- `src/main/resources/static/app/app.js:359`：前台比对类型固定包含 `dir`，没有读取部署能力。
- `src/main/resources/static/app/app.js:574-586`：目录模式直接调用服务器路径比对接口。
- `src/main/resources/static/app/app.js:65`：首页右上角固定显示“本地版本比对”，在服务器模式下语义错误。
- `src/main/java/com/example/jardiff/api/CompareController.java:239-307`：目录上传和服务器路径比对接口没有部署模式限制。
- `src/main/java/com/example/jardiff/api/CompareController.java:546-555`：目录摘要接口没有部署模式限制。
- `src/main/resources/application.properties`：当前没有本地/服务器部署模式配置。
- 结论：前端隐藏只能改善交互，安全边界必须由后端配置和接口校验共同保证。

## 3. 需求与场景

- 需求 R1：系统必须支持 `local`、`server` 两种显式部署模式，默认值为 `local`。
- 需求 R2：`local` 模式必须保留现有目录入口和三个目录 API 行为。
- 需求 R3：`server` 模式必须隐藏前台目录入口；若浏览器保存的上次模式为目录，页面必须回退到 Jar 模式。
- 需求 R4：`server` 模式调用任一目录 API 时必须返回 HTTP 403 和明确错误信息，不能依赖前台隐藏阻止调用。
- 需求 R5：部署模式配置不是 `local` 或 `server` 时必须启动失败，不能静默回退。
- 需求 R6：本地和服务器模式的首页状态文案统一显示“版本比对”，能力接口不得为此增加部署模式字段。
- 场景：本地开发者以默认配置启动，页面可选择目录并按现有流程比对本机路径。
- 场景：运维以 `server` 模式启动，用户只能看到 Jar、文件和文本类型；直接调用目录 API 被拒绝。
- 异常与恢复：前台无法读取部署能力时，目录入口按禁止处理；恢复接口后刷新页面重新读取。配置错误时修正配置并重启服务。

## 4. 存量参考与复用

- 参考对象：`CompareController` 现有构造配置注入、`handleIllegalArgument` 错误响应、前台 `modes` 与 `switchMode` 状态管理、`api.js` 的 `fetchJson` 请求封装。
- 复用内容：沿用 Spring `@Value` 配置注入、现有同源 REST 调用和 Vue 响应式状态，不引入第三方依赖。
- 参考差异：现有 `CompareConcurrencyFilter` 只控制并发，不能表达部署权限；本变更不复用其过滤逻辑，避免把访问策略混入并发职责。

## 5. 已确认决策

- 用户决策：选择内网多人部署模型；服务器部署禁止目录比对，本地运行支持目录比对。
- 用户决策：采用显式 `jardiff.deployment-mode` 配置，不根据 IP、主机名或代理头自动推断环境。
- 用户决策：首页状态统一使用中性文案“版本比对”，不动态显示本地或服务器模式。
- Agent 决策：能力接口只返回 `directoryCompareEnabled`，不向前台暴露更多部署信息；后端仍是唯一安全判断点。
- Agent 决策：服务器模式拒绝全部三个目录接口，避免只禁用路径接口后仍可通过目录上传接口绕过产品约束。

## 6. 验收与质量

- 验收标准：A1-A7 全部满足，且现有非目录比对能力无回归。
- 验收 A1：默认 `local` 模式的能力接口返回 `directoryCompareEnabled=true`，页面显示目录入口。
- 验收 A2：`server` 模式的能力接口返回 `directoryCompareEnabled=false`，页面不显示目录入口。
- 验收 A3：`server` 模式下三个目录 API 分别返回 HTTP 403，错误正文说明服务器模式禁止目录比对。
- 验收 A4：`server` 模式遇到本地保存的 `dir` 模式时自动回到 Jar，不进入不可操作状态。
- 验收 A5：Jar、文件和文本接口及页面入口不受部署模式影响。
- 验收 A6：非法部署模式导致 Spring 应用上下文启动失败。
- 验收 A7：本地和服务器模式首页均显示“版本比对”，页面不再出现固定文案“本地版本比对”。
- 验证方式：Spring Boot 集成测试覆盖能力接口、三个目录 API、默认模式和非法配置；`node --check` 覆盖前端语法；浏览器分别以 local/server 模式验证入口显示和回退行为。
- 安全要求：前端状态不得作为授权依据；所有目录 API 必须在业务方法执行前完成后端拒绝。
- 兼容与回滚：默认 `local` 保持当前本地启动行为；回滚代码和配置项即可恢复原行为。
