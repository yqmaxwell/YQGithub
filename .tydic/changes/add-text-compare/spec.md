# Spec：粘贴文本比对

> 本文件记录已经调查并经用户确认的需求事实。

## 1. 问题与范围

- 当前行为：首页支持 Jar、目录和文件三种比对类型，用户必须先准备两个文件，不能直接粘贴两段文本查看差异。
- 目标行为：在现有比对类型中新增“文本”，用户可在左右粘贴区直接输入旧版和新版文本，提交后进入现有差异结果页。
- 范围：`src/main/resources/static/app/app.js`、`src/main/resources/static/index.html`；复用现有 `src/main/resources/static/app/api.js` 和文件比对后端接口。
- 非目标：不新增后端接口，不引入文本编辑器或语法高亮依赖，不增加语言选择、可编辑文件名或持久化文本历史。

## 2. 项目证据

- 证据：`src/main/resources/static/app/app.js:349-350` 使用 `modes` 统一渲染 Jar、目录和文件比对类型，可以以相同模式增加 `text` 选项。
- `api.js` 已提供 `compareFiles` 和 `loadFilesUnifiedDiff`，分别生成文件比对元数据和统一 Diff 文本。
- `/api/compare/files` 和 `/api/compare/files/unified` 已支持 UTF-8 文本文件，空文件也会被按文本处理。
- 现有文件比对流程已能直接进入结果页，并复用 diff2html 的并排/统一视图、字号调整、变更导航和专注模式。
- 结论：把粘贴文本转成两个 UTF-8 `File` 后，可完整复用现有文件直比链路，无需新增后端能力。

## 3. 需求与场景

- 需求：
  - F1：“比对类型”增加与现有项并列的“文本”选项。
- F2：选择文本模式后，左右区域分别显示“旧版文本”和“新版文本”粘贴框，使用等宽字体并支持多行及滚动。
- F3：任意一侧有内容即可开始比对；两侧都为空时禁用提交，并明确提示“请至少粘贴一侧文本”。
- F4：提交时将两侧文本转换为 UTF-8 文本文件，固定文件名为 `pasted-text.txt`，调用现有文件比对链路。
- F5：比对成功后进入现有结果页，自动选中 `pasted-text.txt` 并显示完整文件差异。
- F6：文本比对继续支持并排/统一切换、代码字号调整、上一处/下一处变更和专注模式。
- F7：返回首页后保留本次粘贴内容；浏览器刷新后清空，不将粘贴文本写入 `localStorage`。
- F8：文本模式隐藏忽略规则、Class、资源和依赖 Jar 等与文本直比无关的配置；切回其他模式后原配置值保留。

- 场景：
  - 双侧有差异：粘贴两段多行文本后提交，结果页显示完整内容和变更块。
- 单侧为空：仅在一侧粘贴文本，结果完整显示为全部新增或全部删除。
- 内容一致：提交相同文本后正常进入结果页，显示“无文本差异”。
- 异常与恢复：请求失败时结束进行态并显示错误，左右粘贴内容保留，用户可直接重试。

## 4. 存量参考与复用

- 参考对象：现有“文件”比对模式和结果页。
- 复用内容：`compareFiles`、`loadFilesUnifiedDiff`、`loadFileDiff`、diff2html 渲染、hunk 导航、字号调整和专注模式。
- 参考差异：文件模式从本地文件选择器取得 `File`；文本模式从左右粘贴内容构造 UTF-8 `File`，其余处理链路一致。

## 5. 已确认决策

- 用户决策：文本作为第四种比对类型，不设置独立快捷页。
- 比对后复用现有差异结果页，不在输入区下方另起一套 Diff。
- 不增加左右名称输入框，使用固定名称。
- 复用文件比对接口，不新增 `/api/compare/text`。
- 不设置新的业务级字符数限制，继续受现有 multipart 上传上限约束。
- Agent 决策：按项目唯一的文件直比范式复用现有接口和结果流程，不创建第二套 Diff 实现。

## 6. 验收与质量

- 验收标准：
  - 首页文本模式的可点击性、选中态和其他比对类型一致。
- 双侧有差异、单侧为空、完全一致、中文及多行文本均能得到正确结果。
- 两侧都为空时不发送请求，单侧为空时允许请求。
- 结果页可使用并排/统一、字号、变更导航和专注模式。
- 返回首页后内容保留，刷新后内容清空。
- 请求失败必须显式提示，不得清空用户输入。
- 验证方式：运行 `node --check src/main/resources/static/app/app.js`、`git diff --check`、`mvn test`；并在真实浏览器中覆盖上述交互场景。
- 适用的安全、性能、兼容、迁移或回滚要求：不将粘贴文本写入前端持久化；不新增依赖、配置、API 或数据迁移；回滚仅涉及两个前端文件。
