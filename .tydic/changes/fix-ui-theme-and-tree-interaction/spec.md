# Spec：UI 重设计与比对交互修复

> 本文件记录已经调查并经用户确认的需求事实。不要为了填模板增加无关内容。

## 1. 问题与范围

- 当前行为：
  1. 当前工作区已换成 GitHub 浅色变量，但仍沿用常驻顶部上传工具栏、粗边框和硬阴影，页面层级与专业比对工具不一致，且尚未完成浏览器视觉验收。
  2. “结构比对”和“差异比对”被设计成左栏 Tab，但右侧始终是 Diff；名称和布局让用户误以为两者是互斥页面。
  3. 结构模式左右两栏原样渲染同一份 `treeData`，`side` 参数没有参与存在性判断，新增或缺失文件会同时显示在两侧，不能表达真实版本结构。
  4. “包含依赖 Jar”的持久化值被反向读取；Jar 按需展开失败会被吞掉，加载状态不会复位。
  5. “上一处/下一处”逐条定位增删行，不是按 diff hunk 导航；快速连续选择文件时也没有防止旧请求覆盖新结果。
- 目标行为：
  1. 比对前使用精简上传工作区，比对后收起为紧凑工具栏；整体采用 GitHub 为主的浅色、低干扰工具界面。
  2. 左侧统一为文件导航，在“变更树/左右结构”之间切换，右侧始终保留当前文件 Diff。
  3. 左右结构模式自动扩展到约 55% 工作区宽度；两侧按 `leftExists/rightExists` 展示真实结构，单侧不存在节点在对应侧保留同一行空占位。
  4. 依赖 Jar 深度索引、内部变更数和按需展开形成完整可恢复流程；错误必须展示并支持重试。
  5. Diff 按真实 hunk 导航，显示当前位置，并保证最后一次文件选择的结果不会被旧请求覆盖。
- 范围：`src/main/resources/static/index.html`、`src/main/resources/static/app/app.js`，以及当前已修改的 `TreeNode.java`、`JarCompareService.java`、`JarCompareServiceTest.java`。
- 非目标：不新增第三方依赖，不新增或改变 API 端点，不改变 Jar 比对核心算法、反编译逻辑、服务端配置或部署方式，不拆分前端工程。

## 2. 项目证据

- 证据：
  1. `src/main/resources/static/app/app.js:47-95`：左栏使用“结构比对/差异比对”Tab，右侧 Diff 位于 Tab 外并始终存在。
  2. `src/main/resources/static/app/app.js:203-274`：`TreeNodeStruct` 接收 `side`，但模板和方法未用它判断 `leftExists/rightExists`。
  3. `src/main/resources/static/app/app.js:303-307`：`includeLib` 使用 `storage.get(...) !== true`，会反转已保存的布尔值。
  4. `src/main/resources/static/app/app.js:460-473`：导航目标是每一条 `.d2h-del/.d2h-ins` 行。
  5. `src/main/resources/static/app/app.js:483-499`：Jar 加载异常被空 `catch` 吞掉，组件的 `nestedLoading` 没有完成态回写。
  6. `src/main/java/com/example/jardiff/core/JarCompareService.java:481-515`：后端已有 `deepCompareLib` 深度索引能力；`TreeNode` 也已有 `leftExists/rightExists/rightStatus/children`，前端无需新增接口即可表达对齐结构。
  7. 当前验证：`mvn test` 共 15 项通过，`node --check` 与 `git diff --check` 通过；前端运行态和视觉仍未验证。
- 结论：后端数据已足够支撑新界面；主要缺口集中在前端信息架构、状态表达、错误恢复和交互验证。

## 3. 需求与场景

- 需求：
  - F1：未产生比对结果时展示 Jar/目录/文件统一入口和左右输入区；产生结果后收起为紧凑顶部工具栏。
  - F2：左侧提供“变更树/左右结构”分段切换，切换不清空当前文件或右侧 Diff。
  - F3：变更树默认只展示变化文件及其祖先目录，支持搜索、状态筛选和 Jar 内部条目展开。
  - F4：左右结构使用同一逻辑行渲染两侧，依据 `leftExists/rightExists` 显示真实节点或空占位；展开状态、行高和垂直滚动同步。
  - F5：左右结构模式自动扩展到约 55%，切回变更树恢复用户原导航宽度；全宽结构模式继续复用同一组件和状态。
  - F6：目录显示聚合变更数；文件同时使用颜色与 `M/A/D/T` 标记，不只依赖颜色传达状态。
  - F7：勾选“包含依赖 Jar”时请求同时携带 `includeLib=true` 和 `deepCompareLib=true`，并正确保存与恢复该设置。
  - F8：Jar 有预索引 `children` 时直接展开，无 `children` 时按需加载；加载失败显示原因和重试入口，成功或失败都结束加载态。
  - F9：点击任一真实文件节点只更新右侧 Diff；全宽结构中选中文件后退出全宽并回到常规布局。
  - F10：Diff 支持并排/统一视图，按 hunk 执行上一处/下一处导航并显示当前位置；无 hunk 时按钮禁用。
  - F11：连续快速选择多个文件时，仅最后一次选择可以更新 Diff 内容、加载态和错误态。
  - F12：桌面保持左右工作区；窄屏改为导航区与 Diff 上下布局，双树可横向滚动，文本和控件不得重叠。
- 场景：
  - 场景一（开始比对）：用户选择模式和左右输入，配置范围后开始比对；成功后上传工作区收起，变更树与右侧 Diff 成为主要界面。
  - 场景二（真实结构对照）：用户切换左右结构，导航区扩展；展开目录时两侧同步，新增或删除节点只在存在侧显示，另一侧保留同一行空位；点击文件后右侧展示差异且模式不变。
  - 场景三（依赖 Jar）：用户开启依赖 Jar，完成深度比对；Jar 显示内部变更数并可展开，点击内部 Class 后右侧显示反编译差异。
  - 场景四（连续浏览）：用户快速点击多个变化文件，右侧最终只显示最后一次选择的文件，并可按变更块前后导航。
- 异常与恢复：
  - 比对请求失败：保留用户已选输入和设置，展示具体错误，允许再次开始比对。
  - Jar 超过预索引限制：节点仍可按需请求 `/api/compare/nested/tree`；失败时保留折叠状态并提供重试。
  - Diff 请求失败：保留当前选中文件和常规布局，在右侧显示错误与重试；不得恢复旧文件结果或吞掉错误。
  - 单侧目录不存在：两侧仍按联合树展开相同行，缺失侧渲染不可点击空占位，不寻找或替换为其他路径。

## 4. 存量参考与复用

- 参考对象：GitHub PR Files Changed 的文件导航与 Diff 主区、GitHub 默认浅色 Diff、VS Code Diff Editor 的变更块导航、DiffChecker 的统一输入入口。
- 复用内容：沿用现有 CSS 变量与 diff2html；复用 `TreeNode`/`TreeNodeStruct` 递归树、`/compare/nested/tree`、`deepCompareLib`、`leftExists/rightExists/rightStatus/children/innerChanges`，不新增 API 或依赖。
- 参考差异：GitHub 只有单一文件树，本工具保留可切换的左右结构；VS Code 的导航按 hunk 而非每条增删行；DiffChecker 的上传入口仅用于比对前状态，比对后必须收起以释放工作区。

## 5. 已确认决策

- 用户决策：
  - 采用单一左侧导航，在“变更树/左右结构”之间切换，右侧始终是 Diff。
  - 左右结构模式自动扩展到约 55%，并保留可拖动分隔线。
  - 单侧不存在节点使用同一行空占位，不隐藏、不在两侧重复显示文件名。
  - 上传区采用比对前完整工作区、比对后紧凑工具栏的两阶段布局。
  - 视觉采用 GitHub 为主的浅色克制风格，仅主操作轻度强调，不保留硬阴影和位移效果。
  - “包含依赖 Jar”继续联动 `includeLib` 与 `deepCompareLib`，不增加独立开关。
- Agent 决策：使用现有联合树和存在性字段完成左右对齐，不创建第二套后端结构接口；全宽模式复用常规左右结构组件；Jar 加载和 Diff 请求的失败必须显式进入可重试状态。

## 6. 验收与质量

- 验收标准：
  - 比对前后两阶段布局正确切换，输入、设置和当前比较对象均清晰可见，工作区无多余常驻上传控件。
  - “变更树/左右结构”切换不影响当前文件和右侧 Diff；左右结构进入时扩展宽度，退出时恢复原宽度。
  - 新增、删除节点只在存在侧显示，缺失侧为空占位；左右展开、行高和滚动同步。
  - 目录聚合数和 `M/A/D/T` 标记正确，状态不只依赖颜色。
  - `includeLib` 设置可正确保存和恢复；开启后请求携带 `deepCompareLib=true`，Jar 显示内部变更数并能展开内部文件。
  - Jar 按需加载成功后结束加载态；失败后显示原因和重试，不能永久“加载中”或静默失败。
  - 结构模式点击文件不切换导航；全宽选择文件后回到常规布局并加载 Diff。
  - 上一处/下一处按 hunk 导航并显示当前位置；无 hunk 时禁用；快速连续选择最终只展示最后一次结果。
  - 桌面、中等宽度和窄屏下无文字、按钮、树行或 Diff 区域重叠。
- 验证方式：先复现 `includeLib` 反转、Jar 永久加载和逐行导航；运行 `mvn test`、`mvn compile`、`node --check`、`git diff --check`；使用真实 fat JAR 完成上述页面流程和多宽度运行态验证。未完成运行态验证时必须明确标记“未验证”。
- 适用的安全、性能、兼容、迁移或回滚要求：不新增依赖和配置；深度索引继续受现有 8MB/个、160MB 总量、40 个数量限制；变更树过滤和目录聚合基于当前结果在前端计算；回滚时恢复前端两文件并保留或移除当前未发布的后端字段改动，具体由实现阶段按实际提交范围执行。
