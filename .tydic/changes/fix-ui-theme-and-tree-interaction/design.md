# Design：UI 重设计与比对交互修复

> 本文件描述已确认需求的技术实现方案。简单变更保持简短，复杂变更按实际影响展开。

## 1. 设计上下文

- 需求来源：`spec.md`
- 设计目标：把当前“上传工具栏 + 两个含义混乱的左栏 Tab + 重复双树”调整为两阶段上传、单一文件导航和持久 Diff 主区，并补齐依赖 Jar、错误恢复、hunk 导航与请求竞态。
- 项目依据：前端是 `index.html` 内联 CSS 与 Vue 3 Composition API 单文件脚本，现有 diff2html、Element Plus 和后端联合树数据足够实现；不引入构建工具、依赖或新 API。

## 2. 技术方案

- 总体方案：
  - 页面状态分为 `setup` 与 `result`：无 `compareId` 时渲染完整输入工作区，有结果时渲染紧凑工具栏和工作区。
  - 左栏使用单一 `navigationMode` 在 `changes` 与 `structure` 间切换，右侧 Diff 组件不随模式销毁。
  - 左右结构继续从同一联合树递归渲染；每一侧根据 `leftExists/rightExists` 决定真实节点或等高空占位，因此无需后端返回两棵树。
  - Jar 按需加载状态提升到以路径为键的共享状态，明确区分 idle/loading/error；Diff 请求使用递增请求序号，只允许最新请求提交结果。
  - hunk 导航基于当前 `.diff-content` 中 diff2html 的 hunk 信息行建立目标列表，不再把每条增删代码行当作一处变更。
- 复用与改动：

  | 文件 | 变更性质 | 说明 |
  |------|----------|------|
  | `src/main/resources/static/index.html` | 修改 | GitHub 浅色视觉、两阶段布局、导航宽度、对齐占位、状态标记和响应式样式 |
  | `src/main/resources/static/app/app.js` | 修改 | 页面结构、导航模式、左右存在性渲染、同步滚动、Jar 状态、hunk 导航和请求序号 |
  | `src/main/java/com/example/jardiff/core/TreeNode.java` | 保留当前改动 | `innerChanges` 默认值及访问器 |
  | `src/main/java/com/example/jardiff/core/JarCompareService.java` | 保留当前改动 | 已深度索引 Jar 的内部变更数计算 |
  | `src/test/java/com/example/jardiff/core/JarCompareServiceTest.java` | 保留并加强验证 | 验证 Jar 节点类型和 `innerChanges` |

- 关键取舍：
  - 不拆分新的前端文件或抽象层，继续使用现有两个递归树组件；只在组件参数和共享状态上补足语义。
  - 变更树与左右结构可以有独立展开状态，但左右结构内部两侧必须共享同一展开集合和滚动位置。
  - 用户拖动得到的变更树宽度单独保存；进入结构模式时使用不小于约 55% 的临时宽度，退出时恢复原值。
  - 状态使用颜色加 `M/A/D/T` 文本；目录展示聚合总数，详细分类通过标题提示，不用单一优先级颜色替代完整信息。
  - 全宽模式复用左右结构组件，不维护第二套树和事件逻辑。

### 2.1 视觉设计体系

- 主体风格：采用 GitHub PR Diff 的浅色、低干扰内容层，以 VS Code 的 Sidebar + Editor 工作台分工组织页面；左侧只负责导航和筛选，右侧只负责当前文件 Diff 及其上下文操作。
- 排版细节：吸收 Swiss Grid 的网格、基线对齐和克制字号层级；等宽字体仅用于路径、状态缩写和 Diff 内容，不扩展为全页装饰语言。
- Awwwards 表达边界：只在比对前上传工作区、空状态和布局转换中使用平衡、对齐、对比和短过渡；结果工作区不采用展示型网页构图。
- 区域映射：

  | 页面区域 | 设计来源 | 落地方式 |
  |----------|----------|----------|
  | 比对前上传区 | Swiss Minimal | 左右输入严格对齐，保留充足留白，仅主比对操作使用明确强调 |
  | 比对后工具栏 | GitHub PR | 紧凑单行布局，稳定展示当前对象和必要操作 |
  | 文件导航 | GitHub TreeView + VS Code Sidebar | 紧凑行高、1px 分隔、稳定缩进，状态颜色与 `M/A/D/T` 并用 |
  | 左右结构 | VS Code Diff Editor | 共享行基线、展开状态和滚动位置，缺失侧保留等高占位 |
  | Diff 主区 | GitHub Diff | 白底、低饱和增删色、内容优先，不额外包装装饰卡片 |
  | 上一处/下一处 | VS Code Editor Actions | 作为当前 Diff 的上下文操作，围绕 hunk 导航并显示位置 |

- 动效限制：上传区收起、导航区宽度变化和 Jar 节点状态可使用 120–180ms 的短过渡；错误和加载必须直接可见，不依赖动画才能理解。
- 明确不采用：全屏 Hero、超大标题、自定义鼠标、视差滚动、长入场或整页转场、非必要横向滚动、硬阴影、位移式悬浮和全局粗黑边框。Neubrutalism 不进入结果工作区。

## 3. 流程与边界

- 正常流程：
  1. 初始状态展示 Jar/目录/文件模式和左右输入；开始比对时保留输入并显示进行态。
  2. 比对成功后写入 `compareId` 与联合树，页面进入结果状态，上传区收起，默认显示变更树。
  3. 切换到左右结构时保存当前导航宽度并扩展结构区；两侧遍历相同节点顺序，存在侧渲染节点，不存在侧渲染占位。
  4. 展开或滚动任一结构树时更新共享状态，另一侧同步；点击真实文件只更新 `selectedPath` 并加载右侧 Diff。
  5. 开启依赖 Jar 时请求携带 `includeLib=true` 与 `deepCompareLib=true`；预索引节点直接展开，未预索引节点进入按需加载状态。
  6. Diff 成功渲染后重建 hunk 目标和当前位置；上一处/下一处只在当前文件目标列表中移动。
  7. 全宽结构使用相同树状态；选中文件后关闭全宽，常规布局继续显示同一选中项并加载 Diff。
- 异常与恢复：
  - 比对失败：展示后端错误，结束进行态，不丢失输入和设置。
  - Jar 加载失败：路径状态变为 error，展示错误和重试；重试前清除该路径错误，成功后写入 `children` 并结束加载态。
  - Diff 请求失败：仅当请求序号仍是最新时写入错误态；旧请求的成功或失败都不得改变当前界面。
  - diff2html 渲染失败：保留现有纯文本转义降级，不插入未转义响应内容。
  - 单侧节点：占位行不可点击，但目录展开仍由联合树路径驱动，保证后代行继续对齐。
- 接口、数据、页面或架构边界：
  - API 边界不变：继续使用 `/compare/jars`、`/compare/diff/unified`、`/compare/nested/tree` 等现有端点。
  - 数据边界不变：联合树继续使用 `leftExists/rightExists/rightStatus/children`；`innerChanges` 缺失时按 0 兼容。
  - 页面边界：Jar/目录/文件共用两阶段壳层；结构能力仅在有树结果时出现，文件直比结果直接显示 Diff。
  - 样式边界：所有新增样式留在 `index.html`，不引入外部样式文件；桌面保持左右布局，窄屏切为上下布局。

## 4. 测试与验证

- 测试接缝：
  - 后端沿用构造内嵌 Jar 的服务测试，验证 `innerChanges`、内部节点状态和深度比对结果。
  - 前端先通过可观察请求参数和页面状态复现 `includeLib` 反转、Jar 永久加载、逐行导航与旧请求覆盖问题，再验证修复后的对应状态转换。
  - 对齐树使用含 modified/added/missing/meta 的联合树样例，逐项核对两侧真实节点、空占位、聚合数和展开同步。
- 关键验证：
  - `mvn test` 与 `mvn compile` 全部成功。
  - JavaScript 语法检查及 `git diff --check` 成功。
  - 使用真实 Spring Boot fat JAR 验证深度索引、按需 Jar 展开、内部 Class Diff、失败重试和设置恢复。
  - 在桌面、中等宽度、窄屏三类视口验证两阶段布局、55% 结构区、同步滚动、全宽返回、hunk 导航和快速文件选择。
- 静态检查或类型检查：前端运行 `node --check`；后端以 Maven 编译和测试为准。项目没有前端类型检查命令，不新增工具链。

## 5. 迁移与回滚

- 迁移：无数据迁移和配置迁移；`TreeNode.innerChanges` 默认 0，前端按字段缺失等同 0 处理；本地存储继续沿用现有键并修正布尔值读取。
- 回滚：恢复 `index.html` 与 `app.js` 即可撤回新信息架构；若后端 `innerChanges` 同期尚未发布，可连同对应服务与测试改动回滚，已发布时保留该兼容字段也不影响旧前端。
